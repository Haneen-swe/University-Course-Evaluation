Core Privacy Architecture (Responsible AI)

Anonymity is structural, not just policy.

The responses table has no student_id column.
The participation_tokens table records whether a student submitted — with no link to what they submitted.
There is no foreign key, shared UUID, or derived field between the two tables.
A database administrator cannot re-identify responses — because the join key does not exist.

Key Design Decisions

DecisionRationale
Anonymity enforced at schema levelCannot be circumvented by application-layer bugs or admin SQL queries
JWT stateless auth + Redis deny-listScales horizontally; logout works without sticky sessions
4-layer module architecture (Router→Controller→Service→Repository)Testable, single-responsibility; business logic never leaks into DB layer
Append-only audit log (INSERT-only DB role)Tamper-evident by database privilege, not just application policy
Minimum response threshold before result releaseProtects small-cohort student anonymity from statistical re-identification
Docker Compose single-server deploymentUniversity-budget friendly; no Kubernetes overhead; portable to cloud
No AI scoring of instructors in v1.0Prevents algorithmic bias influencing employment decisions (Responsible AI)
