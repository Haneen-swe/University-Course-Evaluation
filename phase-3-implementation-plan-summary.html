3 Database
Primary: PostgreSQL 16  |  Cache / Queue: Redis 7  |  File exports: Local filesystem (S3-compatible in production)
StoreTechnologyWhy
Primary RDBMS PostgreSQL 16 ACID transactions (critical for anonymous submission atomicity); JSONB for question options; FK enforcement as second safety layer on anonymity; full-text search on audit logs; append-only table support via DB role privileges
Cache + Queue Redis 7 O(1) JWT deny-list lookups; TTL-managed evaluation drafts; BullMQ job queue storage; rate-limit counters; report cache (15 min TTL)
File store FS / S3 Generated PDF/CSV exports; mounted as Docker volume in dev; swappable to MinIO or AWS S3 in production with no code change

The database contains 12 tables: users, departments, terms, courses, course_offerings, enrollments, eval_form_templates, eval_questions, participation_tokens, responses, audit_logs, notifications.

Privacy invariant: The responses table has no student_id column. The participation_tokens table has no response_id column. There is no join key between the two — anonymity is enforced at schema level, not policy.

6 Docker — Optional or Required?
ContextDocker statusDetail
Local Development Strongly recommended docker-compose.dev.yml spins up Postgres + Redis automatically. Developers can run npm run dev directly if they have local Postgres and Redis installed, but Docker is the zero-friction path.
CI Pipeline Required GitHub Actions spins up a Postgres service container for integration tests. All test runs are containerised by default.
Staging / Production Required The entire production stack (Nginx + API + Worker + Postgres + Redis + Certbot) is defined in docker-compose.yml. Deployment is a single docker compose up -d command.
Summary: Docker is required for production and CI, and strongly recommended for development. The codebase will also include a non-Docker DEVELOPMENT.md guide for developers who prefer native Node.js + local databases — so it is never a hard blocker.
